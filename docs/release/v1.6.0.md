## v1.6.0 — 2026-08-08

Two things changed for you. The console gained a **Documentation** tab that turns the weekly translation-PR recap into one Markdown block per contributor — the standalone `pvzf-make-pr` tool, folded in and made configurable. And the interface was rebuilt on [`@clack/prompts`](https://github.com/bombshell-dev/clack): arrow-key menus with hints, a type-to-filter locale picker, boxed status and result panels, and `Esc` to back out of any screen. Underneath, the codebase was restructured so the size and complexity limits the project declares are now enforced by the linter and checked by CI.

### ✨ Features

- **New `[3] Documentation` tab.** *PR recap → contributor summary* reads a weekly PR recap and writes one Markdown block per contributor: the week, the PR link, the counters (*Nouvelles traductions* / *Traductions ajustées* / *Reviews effectuées*), then the detail of every item that person touched.

  Input needs two header lines, then the usual sections:

  ```markdown
  2026-04-01..2026-04-07
  https://github.com/owner/repo/pull/123

  ## 🌱 Newly Added Plants

  @lafourmiedugaming-collab :
  * **Briseur de Machoir** (`seedType: 1390`)
  ```

- **The lead's *Reviews* block is derived, not written.** Every item authored by somebody else is mirrored under the locale lead, grouped by section then by author. Sections whose name contains `check` are proof-reading passes and are excluded. Counters come from the section names (`new` / `nouveau` / `nouvelle` → *Nouvelles traductions*; `modified` / `modifi` → *Traductions ajustées*).
- **Who the lead is, is now a setting.** `Docs lead` (canonical display name) and `Docs aliases` (every other spelling a recap may use — `@LINDECKER-Charles`, `LINDECKER-Charles`, …) are folded into a single block. Any locale maintainer can use the tool without patching the code; the defaults reproduce the previous hard-coded behaviour exactly.
- **Nothing is written before you have seen it.** The recap is rendered first, its per-contributor table shown in a panel, and the file written only on confirmation. No GitHub API call is made — the PR URL you type is only reinjected into the block headers.
- **`pvzf-console pr-resume [--input <file>] [--output <file>]`** does the same headlessly. With no `--input`, it picks the first candidate `.md` in the working directory, skipping `README.md`, `README.dist.md`, `CHANGELOG.md`, `LICENSE.md`, `CONTRIBUTING.md`, `release.md` and the output file itself.
- **Rebuilt terminal interface.** Arrow-key menus with per-entry hints, `Yes/No` toggles instead of typing `y`, inline validation, and boxed panels for the startup status and every result recap.
- **The locale picker becomes a type-to-filter list past ten locales.** The game ships more than twenty; arrowing through them was slow.
- **`Esc` / `Ctrl+C` leave the current screen** instead of killing the process, and never trigger the action they interrupted. The main menu's *Exit* is the way out.
- **`Docs output`** sets where the contributor summary goes by default (`contribution-summary.md`).

### ⚠️ Compatibility

- **Menu keys shifted.** Documentation is the new `[3]`; **Settings moved from `[3]` to `[4]`**. Both READMEs and the troubleshooting rows are updated.
- **The package now has two runtime dependencies** — `@clack/prompts` and `picocolors` — where previously it had none. Both are installed by npm alongside the CLI; the bundle keeps them external. `npm audit --omit=dev --audit-level=high` is clean and stays a blocking CI gate.
- **Interactive mode now requires a TTY.** Piping into the TUI renders the first menu and exits on EOF. The `diff` and `pr-resume` commands are the supported non-interactive path and are unaffected.
- **Settings files round-trip in both directions.** Three keys are added (`docs_lead_name`, `docs_lead_aliases`, `docs_output`); a 1.5 file loads with the defaults applied, and a 1.6 file read by a 1.5 install simply drops the unknown keys. Downgrading is safe.
- **The `pvzf-make-pr` output is unchanged.** The port was diffed against the standalone tool on its own fixture: byte-for-byte identical.
- **Table cells in reports now escape backslashes.** A value containing `\|` — a regex translation, typically — used to render as an escaped backslash followed by a live cell separator, which split the row it sat in. Such rows are now correct, and differ from the ones 1.5.0 produced.
- **One migration skip changes its wording.** When a destination file already exists *and* its source dump is absent, the migration now reports `no source found` instead of `already present`. Both are skips, nothing is written either way; the existing file is still never touched.
- **Contributors:** `AppDeps` gained `header`, `panel`, `farewell` and `askConfirm`; `askYesNo` is gone (use `askConfirm`); `selectLocalization` returns `null` when cancelled; `askChoice` returns `MENU_CANCELLED`. Internal API only.

### 🧹 Refactor

The whole `src/` tree was restructured against the project's own conventions. No behaviour change — the suite covers the same surface, and the generated reports, diffs and CSVs are identical.

| Check | Before | After |
| --- | ---: | ---: |
| Largest source file | 1305 lines | **260** |
| Files over 300 lines (`src/` + `tests/`) | 10 | **0** |
| Functions over 30 lines | 20 | **0** |
| Signatures over 3 parameters | 14 | **0** |
| Nesting over 3 / complexity over 10 | 4 / 7 | **0 / 0** |
| Lines over 100 characters | 36 | **0** |
| `console.log` outside the CLI layer | 7 | **0** |

- **`cli/app.ts` (1305 lines) split into a dozen modules**: `cli/args.ts` (argv parsing), `cli/main.ts` (entry point), `cli/commands.ts` (headless commands), `cli/deps.ts` (`AppDeps` + the real bindings), `cli/context.ts` (the narrow contract a screen sees), `cli/output.ts`, and one file per screen under `cli/screens/`. `cli/app.ts` is now 157 lines of orchestration.
- **`reporting/markdown.ts` split** into `almanac-report.ts`, `strings-report.ts`, `duplicates-report.ts` and a shared `reporting/output.ts` carrying the `LocaleTarget` context — which also resorbed eight of the fourteen over-long signatures.
- **The eight hand-written `run*` methods became a descriptor registry** (`tools/scan.ts`): each translation type declares how to collect, report and diff, instead of repeating the same loop.
- **`JsonScanner` extracted** from `tools/duplicate-checker.ts` into `core/json-scanner.ts` — it was 45% of a file that is supposed to be about duplicates.
- **`settings.ts` split** into the model (`settings.ts`) and the path resolution plus persistence (`settings-storage.ts`).
- **Diagnostics no longer write to stdout from the domain layer.** Parsers and reporters report through a `core/notices.ts` sink — stderr by default so headless runs keep stdout machine-readable, redirected into the TUI at startup. That also made those branches testable.
- **Duplications removed** into `core/guards.ts`, `core/text.ts` and `core/fs.ts`: `isRecord` existed in four copies, plus `stripBom`, `isNotFound`, `describeError`, `isDir`, `rstrip` and `localeDir`. `"To be translated"` is now single-sourced from `core/models.ts`.
- **Dead code deleted**: the `Map`-or-`Record` tolerance helpers (defending against a case the compiler already ruled out), `enableAnsiOnWindows()` (a documented no-op), and `menuOption()` (a test helper living in production code).
- **`clearConsole()` no longer shells out** to `cls`/`clear` — it writes the ANSI erase sequence, which drops a `child_process` call and the flicker with it.
- **21 leftover `.pyc` files** from the pre-TypeScript Python implementation removed from `src/pvz_console/`; `.venv/`, `venv/`, `__pycache__/` and `*.pyc` added to `.gitignore`.

### 🔧 Internal / Tooling

- **The size and complexity ceilings are now enforced.** `eslint.config.mjs` activates `max-lines` (300), `max-lines-per-function` (30), `max-params` (3), `max-depth` (3), `complexity` (10) and `max-len` (100) as errors, mirroring the project conventions. `max-lines-per-function` is relaxed on `tests/**` only: a `describe` callback is a suite declaration, not a unit of logic.
- **`npm run lint` runs in the main CI workflow.** It previously only ran inside `Security`, which meant a style rule added tomorrow would have been policed by the wrong workflow.
- **`SECURITY.md` added** — supported versions, private reporting channels, response targets, scope, and the checks already running on every push.
- **Test suite: 302 tests across 32 files** (was 240 across 19), 95.62% statements / 87.48% branches / 97.62% functions / 96.64% lines, against a 75% gate.
- **The prompt layer is tested for real.** `src/cli/menus.ts` was excluded from coverage before; it is now measured, driven against in-memory streams with actual key sequences (arrows, `Enter`, `Esc`, `Ctrl+C`).
- Monolithic suites split: `tests/cli/interactive.test.ts` (499 lines) and `tests/tools/migration.test.ts` (452) are gone, replaced by per-subject files under `tests/cli/screens/` and `tests/tools/`.

### 🔒 Dependencies & security

- **Added:** `@clack/prompts` ^1.7.0 (terminal prompts) and `picocolors` ^1.1.1 (ANSI colors). Both are widely used, dependency-light, and stay external to the bundle so npm resolves them at install time.
- **The `esbuild` advisory carried since 1.5.0 is resolved.** GHSA-g7r4-m6w7-qqqr — path traversal in esbuild's development server on Windows — is fixed in 0.28.1, but `tsup` 8.5.1 still declares `^0.27.0` and no release widens it. An `overrides` entry pins the patched version across the tree. Build, typecheck, lint and the full suite pass on it. Remove the override once tsup ships an `^0.28` range.
- `npm audit` now reports **0 vulnerabilities on the whole tree**, not only on production dependencies.
- **Two CodeQL findings fixed** (see *Compatibility* for the user-visible half):
  - `js/incomplete-sanitization` — `markdownCell()` escaped pipes but not backslashes, so a value containing `\|` broke the table row it was written into.
  - `js/file-system-race` — the migration tested a destination with `existsSync()` and wrote to it afterwards. The write now uses the `wx` flag, which makes the check and the write a single syscall: a file created in between can no longer be clobbered. This tool exists to avoid overwriting translators' work, so the window mattered.
- **Actions:** `actions/checkout` 5 → 7.
- **Dependabot is split along the new threat model.** Runtime dependencies reach end users and now get their own pull request (`dependency-type: production`, evaluated first) instead of being folded into the dev-tooling catch-all; that catch-all is scoped to `development` so membership stays deterministic. The rationale comment claimed the package shipped zero runtime dependencies — corrected, along with the same claim in `security.yml`.
- **`typescript` and `typescript-eslint` are grouped together, and TypeScript 7 is deferred.** The plugin peers `typescript >=4.8.4 <6.1.0`, so the two are a lockstep pair; sitting in different groups is what produced a TypeScript 7 pull request that failed `npm ci` with `ERESOLVE` before running a single test. They now move together, and `typescript` 7.x is ignored until the peer range widens. Nothing is owed on our side — the sources already typecheck clean under 7.0.2.
