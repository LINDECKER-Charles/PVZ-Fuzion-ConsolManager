## v1.4.0 — 2026-06-22

The engine is now **full TypeScript** (ESM, Node >=20). The previous Python `pvz_console` package — shipped as a `.pyz` zipapp behind a Node wrapper that detected Python at runtime — is gone, with **zero Python dependency** for users. The CLI, commands, and output formats are unchanged.

### ✨ Features

- **Migration tool overhaul — partial migration instead of all-or-nothing.** Tip migration no longer skips an entire file when a single source string is missing from `translation_strings.json`. The tool now migrates every entry whose source text is translated and omits the rest; when nothing matches it still writes the file as `{}`, so a later `diff` surfaces the missing entries. Existing destination files are never overwritten (skipped).
- **Migration extended to buffs.** "Migrate tips" is now **"Migrate tips & buffs"** and covers `tips_iz.json`, `tips_fs.json`, plus `abyss_buffs.json` (extracts `name` / `introduce` from `Dumps/AbyssBuffData.json`) and `travel_buffs.json` (nested structure preserved from `Dumps/travel_buffs.json`).
- **New "Migrate custom levels" action** in the Translator Tools — generates `customlevel_strings.json`, `customlevel_regexs.json` and `custom_level_data.json` for a locale. The key set comes from the configured source locale (default English, since `Dumps/` has no complete custom-level source), while translations come from the target locale's `translation_strings.json`.

### 🐛 Fixes

- Removed the misleading "Skipped … — N source string(s) missing" message that looked like a bug. The tool no longer skips files because of missing translations — it migrates partially and relies on `diff` to list the gaps.
- **Abyss migration produced an empty file.** `Dumps/AbyssBuffData.json` stores `infos` as a JSON array, which the source extractor rejected (it only accepted objects), yielding `0/0` entries. Container extraction now accepts both arrays and objects, so all 132 `name`/`introduce` strings are picked up.

### ⚠️ Breaking changes

- **Contributors:** Python removed entirely. No more `pvz_console` package, `.pyz`/zipapp packaging, or runtime Python detection — the codebase is TypeScript only.
- **Runtime prerequisite:** **Node >=20** is now required (previously Python 3.10+).
- **Users:** non-breaking. The CLI is unchanged — same commands (`pvzf-console diff --lang <locale> [--out DIR] [--with-diff]`), same TUI, and identical output formats (Markdown reports, diff JSON, Trello CSV). No functional regression.

### 🔧 Internal / Tooling

- Full Python → TypeScript rewrite, ported 1:1: `src/core/` (models, diff), `src/parsers/`, `src/reporting/`, `src/tools/`, `src/cli/`, `src/config.ts`, `src/settings.ts`, entry `src/cli.ts`.
- Bundled with **tsup** to `dist/cli.js`; `bin` now points to the compiled JS (no zipapp, no Python detection).
- Test suite migrated pytest → **Vitest**: 166 tests, ~94% coverage (75% gate).
- CI rewritten for Node (20/22 matrix): typecheck → test:cov → build.
- Internal `tips-migration` module generalized to `migration` (`src/tools/migration.ts`) to cover tips, buffs and custom levels — not visible to end users.
- **CI pipeline:** `test` (with the 75% coverage gate) and `codeql` now run as parallel jobs in the CI workflow. CodeQL upgraded to `codeql-action@v4` (clears the v3/Node 20 deprecation warnings), `javascript-typescript` with the `security-extended,security-and-quality` query suites.
- **Automated security suite** (`security.yml`, parallel jobs, weekly schedule): `npm audit` gate (blocks on high/critical in production deps; full audit informational), **ESLint** with `eslint-plugin-security`, **Semgrep** (`p/typescript` + `p/nodejs` + custom rules), and **Gitleaks** secret scanning.
- **Dependabot:** weekly npm + GitHub Actions updates, grouped (typescript / eslint / vitest / build-tooling / dev).
- **Auto-promotion:** a `promote` workflow fast-forwards `dev` → `main` automatically, but only once **both** CI and Security have passed for the same commit (fast-forward only — never forces or auto-resolves a divergence).
