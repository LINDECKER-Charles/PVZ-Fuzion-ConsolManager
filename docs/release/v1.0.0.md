# 🚀 PVZ Fuzion Console Manager — Release notes

This document summarises every change shipped in this release. Sections are
ordered roughly from *domain/engine* to *packaging/distribution*, not
chronologically.

---

## 🧱 Project restructure

- **Flattened layout.** The legacy `app/` wrapper is gone. Everything now
  lives at the repo root: `src/`, `data/`, `scripts/`, `bin/`, `pyproject.toml`,
  `package.json`.
- **`src/` layout with a proper package**: `src/pvz_console/` with
  sub-modules `cli/`, `core/`, `parsers/`, `reporting/`, `tools/`. No more
  flat `parser/`, `report_builder/`, `interface/` directories.
- **Package entry points**:
  - `python -m pvz_console` via `src/pvz_console/__main__.py`.
  - `pvz-console` console-script entry in `pyproject.toml`.
  - `pvzf-console` npm binary in `package.json`.
- **`pyproject.toml`** rewritten: name `pvz-console`, no runtime deps,
  `setuptools` package-finder configured for the `src/` layout, entry script
  wired to `pvz_console.cli.app:main`.

## 🧠 Domain model + diff engine

- **`core/models.py`** — dataclasses (`slots=True`) for the five domain
  entities: `Plant`, `Zombie`, `Achievement` (all subclass `AlmanacEntry`,
  carrying the raw JSON dict for verbatim reporting), `StringEntry` (flat
  key/value diff record), `TrelloCard`.
- **`core/diff.py::missing_by_id`** — O(n + m) set-based lookup replacing
  the original O(n·m) nested loop in `entry_comparator.py`.
- **`parsers/strings.py`** — generic flat-dict diff (`diff_file`) plus a
  nested variant (`diff_nested_file`) that flattens
  `{category: {id: value}}` into compound `category:id` keys. Feeds the
  Travel Buffs diff without extra code.

## 🔍 New diffs

| Type              | Source                                               | File name           |
| ----------------- | ---------------------------------------------------- | ------------------- |
| **Strings (UI)**  | `Strings/translation_strings.json`                   | `missing_strings.md`|
| **Regex**         | `Strings/translation_regexs.json`                    | `missing_regexs.md` |
| **Tips IZ**       | `Strings/tips_iz.json`                               | `missing_tips_iz.md`|
| **Tips FS**       | `Strings/tips_fs.json`                               | `missing_tips_fs.md`|
| **Abyss buffs**   | `Strings/abyss_buffs.json`                           | `missing_abyss_buffs.md` |
| **Travel buffs**  | `Strings/travel_buffs.json` (nested)                 | `missing_travel_buffs.md`|

Every diff also distinguishes **missing keys** (absent from the locale)
from **empty values** (present but blank) and lists them separately.

## 📝 Report output

- **Almanac reports** — condensed `name + id` header followed by a fenced
  ```` ```json ```` block with the raw translation entry (braces included)
  so translators can copy/translate/paste directly into the source file.
- **Flat reports** — two sections per report: *Missing Keys* as a compact
  JSON object, *Empty Values* as a Markdown table.
- **Grouped by locale**: `reports/<Locale>/<kind>.md` (was
  `reports/<kind>/<prefix>_<Locale>.md`). Empty categories produce no file.

## 🛠️ Translator tools

### Tips migration

- `tools/tips_migration.py` recreates `tips_iz.json` / `tips_fs.json` from
  matches in `translation_strings.json`.
- **All-or-nothing**: if any Chinese tip text from the dump is missing from
  the locale's translation strings, the file is **not** written and the gap
  count is reported. No partial migrations.
- Already-present targets are preserved — never overwritten.

### Trello CSV export

- `tools/trello_export.py` + `reporting/trello_csv.py` produce **one CSV per
  category** under `exports/<Locale>/`:
  `trello_Plants.csv`, `trello_Zombies.csv`, `trello_Achievements.csv`,
  `trello_Strings.csv`, `trello_Regex.csv`, `trello_Tips_IZ.csv`,
  `trello_Tips_FS.csv`, `trello_Abyss_Buffs.csv`,
  `trello_Travel_Buffs.csv`.
- CSV columns: `Name, Description, Labels, List` (every row quoted with
  `csv.QUOTE_ALL`).
- **Descriptions are JSON-fenced**:
  - Almanac cards: full source JSON (braces kept) wrapped in
    `` ```json ``…`` ``` ``.
  - Flat cards: a `"key": "value"` snippet wrapped in the same fence.
  - Escape sequences (`\n`, `\"`, `\\s`, unicode escapes) are kept literal —
    bytes-for-bytes identical to the source file.
- **Companion `trello_README.md`** generated alongside the CSVs. It:
  - Lists the *exact* Trello label to create (configurable via settings).
  - Enumerates the *exact* Trello lists to create — dynamically built from
    the CSVs actually produced.
  - Walks the user through the *Import to Trello by Blue Cat (CSV, Excel)*
    Power-Up, step by step.
- Tips/buffs CSVs are **always generated**, even when the locale has no
  source file yet — in that case every English key becomes a card.

## ⚙️ Settings + persistence

- `settings.py` introduces `AppSettings` (dataclass) persisted as
  `settings.json` at the repo root (gitignored). Unknown keys are ignored
  → forward/backward compatible.
- Editable keys:
  - `project_root` (abs path to `PvZ_Fusion_Translator/`)
  - `source_locale` (default `English`)
  - `color`, `accent_color` (ANSI palette)
  - `density` (`compact` / `comfortable` / `spacious`)
  - `show_emoji`, `show_banner`
  - `trello_label` (default `To be translated`).
- **Settings menu** wired into `[3] Settings` with submenus for each key.
  Validates project-root changes before accepting (checks
  `Localization/` exists).
- **Startup validation** — invalid project root shows a warning on launch
  and gates every tool action with a friendly `❌` message instead of
  crashing on `os.listdir`.
- **Auto-discovery** — if `project_root` isn't set, `config.py` probes four
  fixed locations (install sibling → one level up → cwd → cwd parent). Not
  recursive. First match wins, canonical sibling returned otherwise for
  stable error messages.

## 🎨 CLI look & feel

- `cli/theme.py` — `THEME` singleton exposing `primary`, `accented`,
  `colorize`, `emoji`, `blank_lines`. ANSI colors + Windows VT100
  enablement via `ctypes.windll.kernel32.SetConsoleMode`.
- `cli/menus.py` renders box-framed sections, right-aligned option keys,
  column-major locale picker (3 columns), consistent `❯ ` prompts.
- `cli/banner.py` loads `data/title.md` from the filesystem **or**
  `importlib.resources.files("pvz_console") / "data" / "title.md"` when
  running from inside a `.pyz`.
- UTF-8 reconfigure on stdout/stderr at startup so emojis survive pipes,
  cp1252 consoles, etc.

## ⚡ Headless CLI

- `argparse` dispatch at the top of `cli/app.py::main()`:
  - No sub-command → interactive TUI (previous `main()` body factored into
    `_run_interactive()`).
  - `diff --lang <locale> [--out <dir>]` → runs every diff type for one
    locale and exits.
- Exit codes: `0` success, `2` invalid locale / source locale / missing
  project root.
- Validates the locale before running (lists available locales on error).

## 🏗️ Build + distribution

### Shell wrappers (moved to `scripts/`)

- `scripts/run.sh` / `scripts/run.bat` — launch the TUI from source with
  `PYTHONPATH=src`. Detect `python` / `python3` / `py`, reject the Windows
  Store stub by matching `"Python 3.*"` in `--version` output.
- `scripts/build.sh` / `scripts/build.bat` — stage `src/pvz_console/` +
  `data/` into a temp directory, call `python -m zipapp`, copy
  `README.dist.md` → `dist/README.md`, clean up the staging dir.
- All four scripts `cd "$(dirname "$0")/.."` so they always run from the
  repo root, no matter where they're invoked from.

### npm wrapper (`bin/`)

- `bin/pvzf-console.js` — auto-detects Python 3.10+, prints the
  [python.org/downloads](https://www.python.org/downloads/) link on
  failure, forwards every argv to `dist/pvzf_console.pyz`.
- `bin/build.js` — cross-platform builder, exported as a Node module with
  `buildPyz()`, `detectPython()`, `pythonMissingMessage()`. Still runnable
  standalone via `node bin/build.js`.
- **Lazy rebuild**: if `dist/pvzf_console.pyz` is missing at launch
  (fresh install from a stripped tarball, deleted archive, dev checkout
  without build), the CLI rebuilds it in-place from the shipped `src/` +
  `data/`. Shows `pvzf-console: bundled archive not found, building it
  now…` once, silent on subsequent runs.
- `package.json`:
  - `files`: `bin/`, `dist/`, `src/`, `data/`, `README.md`,
    `README.dist.md` (tarball is self-sufficient).
  - `scripts.build` + `scripts.prepublishOnly` → `node bin/build.js`.

### Documentation

- **`README.md`** (repo-level) — exhaustive: install paths, full menu
  reference (source file → output file per type), headless CLI reference,
  settings table, project structure, build & distribute, troubleshooting
  table, contributing guide with module boundaries and a 4-step drill for
  adding a new translation type.
- **`README.dist.md`** — translator-focused, ships inside the `.pyz`
  archive (`dist/README.md`) via all three builders. 30-second quickstart,
  menu walkthrough, settings, troubleshooting — no mention of source /
  contributing / building.
