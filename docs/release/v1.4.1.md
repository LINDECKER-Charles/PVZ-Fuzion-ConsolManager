## v1.4.1 — 2026-07-14

This patch updates `pvzf-console` for the new `travel_buffs.json` structure used by `PvZ_Fusion_Translator`. Travel buffs are now matched by their `category:id` pair, while the complete `name` and `desc` payload is preserved in every generated report and diff.

### 🐛 Fixes

- **Added support for the new travel-buff format.** The console now handles entries shaped as `{ category: { id: { name, desc } } }` instead of assuming that each ID points directly to a string.
- **Travel buffs are now compared by ID.** If a `category:id` pair exists in the target locale, the buff is considered present regardless of the current contents of its `name` and `desc` fields. If the ID is absent, it is reported as one missing buff rather than as multiple missing fields.
- **Descriptions are preserved.** Missing-buff Markdown reports, `travel_buffs_diff.json` files, and Trello cards now include the complete source object with both `name` and `desc`.
- **Travel-buff migration supports nested fields.** Migration from `Dumps/travel_buffs.json` recursively preserves the new structure and translates both fields when translations are available.
- **Duplicate detection supports nested travel buffs.** Duplicate values are detected through the complete nested structure instead of stopping at the ID level.

### ⚠️ Compatibility

- The legacy `{ category: { id: value } }` format remains supported for locales that have not migrated yet.
- No CLI command has changed. Existing interactive and non-interactive workflows continue to work as before.

### 🔧 Internal / Tooling

- Added a dedicated travel-buff entry model so reports and exports can retain the complete source payload.
- Added regression coverage for ID-based comparison, `name` / `desc` preservation, migration, duplicate detection, Markdown output, JSON diffs, and Trello exports.
- Test suite: **172 tests passing**. Typecheck, lint, and production build also pass.
- Verified against the current English and French files from `PvZ_Fusion_Translator`: **22 missing French travel-buff IDs** are now reported correctly.
