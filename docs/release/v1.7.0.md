## v1.7.0 — 2026-11-12

Every tool of the console now runs as a one-shot command, so scripts, CI and coding agents can drive the whole toolkit without a terminal — with `--help` to discover it and `--json` to read the results. A new **AI agents** screen installs a ready-made Agent Skill into the coding agents found on your machine (Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot…), so they know how to use those commands. Since 1.6.0 the project also gained a website with an interactive replica of the console, and a full documentation set.

### ✨ Features

- **Every tool is a headless command.** `duplicates`, `trello`, `migrate-tips` and `migrate-levels` join `diff` and `pr-resume`:

  ```bash
  pvzf-console diff --lang French --with-diff
  pvzf-console duplicates --lang French --json
  pvzf-console trello --lang German --out ./exports
  pvzf-console migrate-tips --lang Spanish
  pvzf-console migrate-levels --lang Spanish
  pvzf-console pr-resume --input recap.md --output docs/contributions.md
  ```

  The two `migrate-*` commands write into the game folder with the same guarantee as the menu: an existing locale file is never overwritten.
- **`--json` on every command** prints exactly one JSON document on stdout — `{ "ok": true, "command": …, "result": { … } }` with the counts and the paths written, or `{ "ok": false, "command": …, "error": { "message": …, "exitCode": … } }` — while warnings stay on stderr. Argument errors are caught before any command runs and stay a single `error:` line on stderr with exit code `2`. `diff` now reports the missing count of each category.
- **`--project-root <dir>`** points a single run at a `PvZ_Fusion_Translator/` folder without saving it to the settings.
- **`--help` / `-h`** lists the commands and `<command> --help` documents one of them; `--version` prints the installed version.
- **New `[5] AI agents` screen.** Choose *Every project* (the agents' folders in your user directory) or *This folder only* (the working directory), see which agents are detected and which already have the skill, tick, confirm. The skill ships inside the npm package, so reinstalling it from this screen after an upgrade keeps it in step with the CLI. With no agent detected, or on Node.js older than 22.20, the screen prints the equivalent command instead:

  ```bash
  npx skills add LINDECKER-Charles/PVZ-Fuzion-ConsolManager --skill pvzf-console
  ```

- **The `pvzf-console` Agent Skill** (`skills/pvzf-console/SKILL.md`) tells an agent how to run the CLI: always pass a command and `--json`, how the game folder is found, the six commands, the output shape and the exit codes — and to ask the user before a migration writes into the game folder.
- **Website** at <https://lindecker-charles.github.io/PVZ-Fuzion-ConsolManager/>, with an interactive, keyboard-driven replica of the console: four autoplay scenarios, or take the keyboard and walk the menus yourself. It also serves [`llms.txt`](https://lindecker-charles.github.io/PVZ-Fuzion-ConsolManager/llms.txt), an index of the documentation for language models.
- **Documentation set.** The README became a front page. The manual moved to `docs/guide/` (usage, configuration, catalog, outputs, troubleshooting) and `docs/internals/architecture.md`, next to `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` and the history of every version under `docs/changelog/` and `docs/release/`. `AGENTS.md` carries the repository's rules for coding agents that contribute to it.

### ⚠️ Compatibility

- **A third runtime dependency: [`skills`](https://github.com/vercel-labs/skills)**, the Agent Skills installer behind `[5] AI agents`. It requires Node.js 22.20+, so on Node.js 20 – 22.19 `npm install` prints an `EBADENGINE` warning for it. The warning is harmless: the library is loaded only when that screen installs something, everything else still runs on Node.js 20, and the screen falls back to printing the `npx skills add` command. With `engine-strict=true` in your npm configuration the install fails instead — upgrade Node.js or lift that setting.
- **The interactive console refuses to start without a terminal.** Launched with no command while stdin or stdout is piped or redirected, it used to render the first menu and exit on EOF; it now prints `error: the interactive console needs a terminal (stdin and stdout must be a TTY).` and exits with code `2`. Scripts call a command instead.
- **Existing `diff` and `pr-resume` invocations keep working.** `-h` is now accepted as an alias of `--help`; every other option stays long-form only, and an unknown command or option still fails with exit code `2`.
- **Settings are unchanged.** No key was added or renamed; a 1.6 settings file loads as-is, and downgrading stays safe.
- **Contributors:** the headless layer moved to `src/cli/headless/` — one registry record per command feeds the parser, the help screens and the dispatch — replacing `src/cli/args.ts` and `src/cli/commands.ts`. `AppDeps` gained `askMultiSelect`. `CLAUDE.md` is now tracked and only imports `AGENTS.md`: a local, previously ignored `CLAUDE.md` is replaced when you pull, so keep a copy first.

### 🔧 Internal / Tooling

- **Test suite: 382 tests across 41 files** (was 302 across 32), 95.20% statements / 87.01% branches / 96.58% functions / 96.17% lines, against a 75% gate. The `skills` gateway is exercised against the real library in a temporary project on Node.js 22.20+; its old-Node.js fallback is covered separately.
- **The website is a second, independent bundle** (`npm run build:site`): linted with the same size and complexity limits, type-checked, and unit-tested under `tests/site/`, which counts towards the coverage gate. CI builds it in every job, and `pages.yml` deploys it on every push to `main` that touches it.

### 🔒 Dependencies & security

- **Added:** `skills` ^1.8.1 (runtime). It is loaded lazily, stays external to the bundle, and is only ever handed the skill folder of the installed package with its telemetry turned off: installing the skill makes no network call.
- **`@clack/prompts`** 1.7.0 → 1.8.1 (lockfile; the `^1.7.0` range is unchanged). Its narrower cancel type needed a type-only fix in the locale picker; behaviour is unchanged.
- **Vitest 4.1.12** clears the `@vitest/mocker` advisories [GHSA-qxg6-89mg-rqv8](https://github.com/advisories/GHSA-qxg6-89mg-rqv8) and [GHSA-xp26-3454-mjgp](https://github.com/advisories/GHSA-xp26-3454-mjgp) — development tooling only, never shipped.
- **Development tooling** kept current through three Dependabot batches: TypeScript with `typescript-eslint`, the ESLint group, `tsx`, Vite 8.3.5. Vitest stays on 4.x while Node.js 20 is supported, since Vitest 5 requires Node.js 22.12+. Dependabot now runs weekly; the cooldown still applies.
- **Actions:** `github/codeql-action` 4.37.4 → 4.38.3.
- `npm audit --omit=dev --audit-level=high` reports **0 vulnerabilities** on production dependencies and stays a blocking CI gate. The full tree reports 10 moderate advisories, all in development tooling: `minimatch` ([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)), pulled in by ESLint 10 and `typescript-eslint`. None of it reaches the published bundle; the only fix offered today downgrades ESLint to 9, so it is tracked until upstream ships a patched range.
