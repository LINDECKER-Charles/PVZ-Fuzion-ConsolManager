v1.6.0 adds a Documentation tab and a headless `pvzf-console pr-resume` command that turn the weekly
translation-PR recap into per-contributor Markdown blocks (a TypeScript port of the standalone
`pvzf-make-pr` tool), driven by three new settings (`docs_lead_name`, `docs_lead_aliases`,
`docs_output`). The interactive console is rebuilt on `@clack/prompts` (arrow-key menus,
type-to-filter locale picker, Esc/Ctrl+C leaving a screen without triggering its action), which
makes `@clack/prompts` and `picocolors` the package's first runtime dependencies; `Settings` moves
from `[3]` to `[4]`. Internally the 1305-line `cli/app.ts` is split into
args/main/commands/deps/context/output plus one file per screen, the Markdown reporters and settings
storage are split by responsibility, and ESLint now enforces the size/complexity limits declared in
CLAUDE.md, with lint added to the CI workflow. Two CodeQL alerts (backslash escaping in Markdown
table cells, a check-then-write race in the migration tool) are fixed, esbuild is pinned to 0.28.1
for GHSA-g7r4-m6w7-qqqr, and the Dependabot grouping is reworked; a SECURITY.md policy is added and
both READMEs are updated.

## Added

- New `[3] Documentation` screen in the TUI (`src/cli/screens/documentation.ts`) with a single
  entry, `[1] PR recap → contributor summary` (hint shows the configured lead): asks for the recap
  file (pre-filled with the first candidate `.md` in the working directory, alphabetically, skipping
  `README.md`, `README.dist.md`, `CHANGELOG.md`, `LICENSE.md`, `CONTRIBUTING.md`, `release.md` and
  the output file itself) and the output file (default from the *Docs output* setting), renders the
  result in dry-run mode, shows a per-contributor `new / mod / rev` table and writes only after a
  `Write <file>?` confirmation. Main menu becomes `[1] Show what's missing`, `[2] Translator tools`,
  `[3] Documentation`, `[4] Settings`, `Exit`.
  ([`2f82b4d`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/2f82b4d))
- New headless command `pvzf-console pr-resume [--input FILE] [--output FILE]` (long flags only,
  `--name value` or `--name=value`), the non-interactive equivalent of the Documentation tab. Exit
  codes: `0` success, `1` runtime failure (recap missing, unreadable or lacking its two header
  lines), `2` usage error. Argument parsing now lives in `src/cli/args.ts` (`parseCliArgs`,
  `CliArgError`, `USAGE_EXIT_CODE = 2`) and also covers the existing `diff --lang <LOCALE> [--out
  DIR] [--with-diff]` command; unknown commands, unrecognised arguments and missing option values
  are rejected argparse-style (`error: unrecognized arguments: …`, `error: argument --x: expected
  one argument`) with exit code 2.
  ([`2f82b4d`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/2f82b4d))
- New `src/tools/pr-resume/` module, a TypeScript port of the standalone `pvzf-make-pr` CLI split by
  responsibility: `parser.ts` (first two non-empty lines are the header — period and PR URL —
  `PrRecapParseError` otherwise; section/contributor/bullet detection; PR number from `/pull/(\d+)`,
  `?` when absent), `service.ts` (per-contributor aggregation, `new`/`modified` counters from
  section-name markers, derived *Reviews* block for the lead excluding `check` sections since the
  recap never states reviews explicitly), `renderer.ts` (French Markdown output: `Nouvelles
  traductions`, `Traductions ajustées`, `Reviews effectuées`), `period.ts` (ISO range → `dd/mm/yy →
  dd/mm/yy`), `index.ts` (orchestration, `resolveRecapInput`, `resolveSummaryOutput`,
  `buildContributionSummary`, `DEFAULT_SUMMARY_OUTPUT = "contribution-summary.md"`,
  `RecapNotFoundError`). The locale lead is a `LeadIdentity` parameter (name + aliases) rather than
  a hard-coded name and `dryRun` renders without touching the disk. Output verified byte-for-byte
  against the original tool's fixture; tests under `tests/tools/pr-resume/` (`index`, `parser`,
  `service`).
  ([`737bb56`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/737bb56))
- Three new persistent settings, stored as `docs_lead_name` (default `Charles LINDECKER`),
  `docs_lead_aliases` (default `["@LINDECKER-Charles", "LINDECKER-Charles"]`) and `docs_output`
  (default `contribution-summary.md`) in `settings.json`, editable from the Settings screen via the
  new entries `[9] Change documentation lead` (name & comma-separated aliases, de-duplicated) and
  `[10] Change default summary output` (`Reset to defaults` becomes `[11]`). Older files load with
  the defaults; older installs reading a newer file drop the unknown keys, and a hand-edited alias
  list is filtered down to non-empty strings (`readAliases` in `settings-storage.ts`).
  ([`2f82b4d`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/2f82b4d))
- New `SECURITY.md`: what a vulnerability looks like for a local-first CLI, supported versions
  (latest minor only, `1.6.x`), private reporting channels (GitHub security advisory, preferred, or
  email with `SECURITY` in the subject), response targets (acknowledgement 5 business days, initial
  assessment 10), out-of-scope items (e.g. running the CLI on an end-of-life Node release), and the
  checks already running in the `Security` workflow (`npm audit --omit=dev --audit-level=high`,
  CodeQL, Semgrep with `.semgrep.yml` + `p/typescript`/`p/nodejs`, Gitleaks over the full history).
  ([`6a0e35d`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/6a0e35d))

## Changed

- Interactive prompts rebuilt on `@clack/prompts` (`src/cli/menus.ts`): arrow-key `select` menus
  with hints and a 12-row scroll window (`MAX_VISIBLE_ITEMS`), Yes/No `confirm` toggles, `text`
  inputs, boxed status/result panels (`note`/`log`/`outro` in `cli/output.ts`), and a locale picker
  that switches to a type-to-filter `autocomplete` (`type to filter…`) above 10 locales
  (`AUTOCOMPLETE_THRESHOLD`). `Esc`/`Ctrl+C` leave the current screen without triggering the
  interrupted action — menus return the `MENU_CANCELLED` (-1) sentinel and the locale picker returns
  `null` instead of reusing the `Back` key, which some menus give another meaning; the main menu's
  *Exit* is the only way out.
  ([`2f82b4d`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/2f82b4d))
- `clearConsole()` writes the ANSI erase sequence `\x1b[2J\x1b[3J\x1b[H` (only when stdout is a TTY)
  instead of spawning `cls`/`clear`; screen headers are a clack `intro` bar carrying the upper-cased
  title. ([`2f82b4d`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/2f82b4d))
- Parsers and reporters no longer write to stdout. Diagnostics (e.g. `Error reading <file>` from
  `parsers/loaders.ts`) go through a `core/notices.ts` sink (`reportNotice`, `setNoticeSink`,
  `resetNoticeSink`) — stderr by default so headless runs keep stdout machine-readable, redirected
  into the TUI's own warning output at startup by `cli/main.ts`.
  ([`2f82b4d`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/2f82b4d))
- `package.json` description now mentions turning the weekly PR recap into contributor
  documentation; keywords gain `tui`, `changelog`, `documentation`.
  ([`2f82b4d`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/2f82b4d))

## Fixed

- `markdownCell()` in `src/reporting/output.ts` now escapes backslashes (`\` → `\\`) before pipes.
  Previously a value containing `\|` (regex translations hit this) came out as an escaped backslash
  followed by a live `|`, splitting the report table row. New `tests/reporting/output.test.ts` plus
  a case in `tests/reporting/strings-report.test.ts`. Closes the CodeQL `js/incomplete-sanitization`
  alert. ([`ec0b98a`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/ec0b98a))
- `src/tools/migration.ts` writes migrated files with the `wx` flag so the existence check and the
  creation are one syscall; an `EEXIST` refusal (new `isFileAlreadyExists()` guard in
  `core/guards.ts`, sharing a private `hasErrnoCode()` helper with `isFileNotFound()`) yields
  `skippedExists`. The previous `existsSync()`-then-write window could silently overwrite a file
  saved in between (editor save, second run). Consequence: a destination that already exists whose
  source dump is absent now reports `sourceMissing` instead of `skippedExists` — both are skips and
  neither writes. Regression test in `tests/tools/migration-tips.test.ts`. Closes the CodeQL
  `js/file-system-race` alert.
  ([`8110fe9`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/8110fe9))

## Security

- esbuild pinned to `^0.28.1` through an npm `overrides` entry in `package.json` (lockfile: 0.27.7 →
  0.28.1 for every platform package) for GHSA-g7r4-m6w7-qqqr, a path traversal in esbuild's
  development server on Windows affecting `>= 0.27.3 < 0.28.1`. The vulnerable version came through
  tsup 8.5.1 (`esbuild: ^0.27.0`) with no tsup release widening the range. Build, typecheck, lint
  and the suite pass; `npm audit` now reports zero vulnerabilities on the full tree. The override is
  to be dropped once tsup ships a `^0.28` range.
  ([`469738e`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/469738e))

## CI

- `npm run lint` now runs in the CI workflow (`Lint (style + CLAUDE.md size/complexity limits)`
  step) ahead of the typecheck — it previously ran only in the Security workflow, so a style rule
  would have been policed by the wrong pipeline. The production-audit gate comment in `security.yml`
  is corrected: the package ships two runtime dependencies (`@clack/prompts`, `picocolors`), so a
  high/critical advisory there lands on end users' machines and is treated as blocking.
  ([`7099b82`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/7099b82))
- Dependabot (`.github/dependabot.yml`): a `runtime` group (`dependency-type: production`) is added
  first so `@clack/prompts` and `picocolors` are reviewed in their own pull request (a dependency
  matches the first group it qualifies for), and the catch-all `other-dev` group is scoped to
  `dependency-type: development` so membership no longer depends on the exclusion list staying
  exhaustive. The threat-model comment is rewritten in two halves (runtime deps shipped to users vs.
  build tooling reaching CI and maintainer machines only).
  ([`05b0875`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/05b0875))
- Dependabot: `typescript-eslint` / `@typescript-eslint/*` move from the `eslint` group into the
  `typescript` group (with `typescript` and `@types/*`) because `typescript-eslint` 8.66.0 peers
  `typescript >=4.8.4 <6.1.0`; splitting them is how #18 bumped TypeScript to 7 alone and failed
  `npm ci` with ERESOLVE. A new `ignore` entry keeps `typescript` `7.x` out until the plugin widens
  its peer range (sources already typecheck under 7.0.2). The grouping rationale comment is extended
  to cite #18 next to the earlier vitest repair (3026f97).
  ([`c2ee3f1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/c2ee3f1))

  `max-lines-per-function` is switched off for `tests/**` only, since a `describe` callback is a
  suite declaration. The 77 breaches measured before the refactor (see the table in the release

  real bindings), `cli/context.ts` (`AppContext`, what a screen may know), `cli/output.ts`, and one

  `duplicates`, `documentation`, `settings`, `settings-editors`, `menu-loop`). `src/config.ts` drops
