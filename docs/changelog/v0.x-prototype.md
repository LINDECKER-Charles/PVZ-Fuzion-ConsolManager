First prototype of the PVZ Fuzion Console Manager, written in Python (`requires-python >= 3.10`,
uses `match` statements) with a documented `zipapp` build (`python_console.pyz`). It reads the
English and translated almanac JSON files of the sibling `PvZ_Fusion_Translator` checkout
(`LawnStringsTranslate.json`, `ZombieStringsTranslate.json`, `AchievementsTextTranslate.json`),
diffs plants, zombies and achievements by id against the English reference, and writes one Markdown
report per locale and per entity type under `reports/{plants,zombies,achievements}/`. An interactive
console menu drives the comparison; the "Check files integrity" and "Settings" entries are stubs.
The tree was moved under `app/` at the end of the range. Never tagged, never published.

## Added

- Almanac parser (`src/parser/parser.py`): `get_plant_almanac`, `get_zombie_almanac`,
  `get_achivements` (sic) load `LawnStringsTranslate.json`, `ZombieStringsTranslate.json` and
  `AchievementsTextTranslate.json` from a locale's `Localization/<locale>/Almanac/` folder (opened
  with `utf-8-sig`, i.e. BOM tolerated), returning `{}` and printing a `✗ Error reading ...` line on
  any exception; `get_all_localization` lists the sub-directories of a `Localization/` folder.
  ([`cb28341`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/cb28341))
- Domain model and comparator (`src/parser/object.py`): `Entity` base class (id, name, introduce)
  with `Plant` (id = `seedType`, plus `info`, `cost`), `Zombie` (id = `theZombieType`, plus `info`)
  and `Achievement` (id = `achievement`, name = `Name`, introduce = `Text`); `EntryPath(root,
  location)` builds `<root>/Localization/<location>/Almanac/`;
  `get_plants`/`get_zombies`/`get_achievements` load and map one locale; `get_entity_dict` indexes
  entities by id; `compare_lists(a, b)` returns the entries of `a` whose id is absent from `b`
  (nested-loop scan).
  ([`cb28341`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/cb28341))
- Entry comparator (`src/parser/entry_comparator.py`): `compare_json_plant`, `compare_json_zombie`,
  `compare_json_achievement(root, location_a, location_b)` return the entries of locale A missing in
  locale B. Initially shipped with a `__main__` block resolving `../../../PvZ_Fusion_Translator`
  relative to the file and printing the number of missing plants for every locale against `English`.
  ([`cb28341`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/cb28341))
- First Markdown report builder (`src/report_builder/need_trad.py`, French labels):
  `build_plant_report(plants, localization, output_dir)` writes `missing_plants_<locale>.md` listing
  each missing plant with name, id, description, detailed info and cost, and prints `✅ Aucune plante
  manquante.` when nothing is missing. `src/console.py` gets its first content: a batch script that
  iterates every locale of `<root>/Localization` against `English`, builds the plant report into
  `reports/plants` and prints the per-locale count (root resolved as `../../PvZ_Fusion_Translator`
  relative to `console.py`).
  ([`10e58e1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/10e58e1))
- `build_zombie_report` and `build_achievement_report` writing `missing_zombies_<locale>.md` and
  `missing_achievements_<locale>.md`; a shared `_write_header` emits an English header (title,
  locale, total missing entries, "Generated automatically by PVZ Fuzion Console Manager"), a table
  of contents and a summary section. The plant report switches to English labels (`seedType`,
  `Introduce`, `Info`, `Cost`; zombies/achievements use `ID`, `Description`, `Detailed Info`) and an
  empty list now returns silently instead of printing a message.
  ([`3b421c9`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/3b421c9))
- Interactive console (`src/console.py` + new `src/interface/interface.py`): banner `=== PVZ Fuzion
  Consol Manager ===`, main menu `[0] Show what's missing`, `[1] Check files integrity`, `[2]
  Settings`, `[3] Exit`; locale picker (`[-1] All` then one entry per locale — any input that is not
  a valid index selects all locales); translation-type picker (`[-1] All`, `[0] Plants`, `[1]
  Zombies`, `[2] Achievements`). Option 0 compares the chosen locale(s) against `English`, writes
  reports under `reports/plants`, `reports/zombies`, `reports/achievements` and prints `Total
  missing entries found: <n>`. Options 1 and 2 (and any unknown choice) print "This feature is under
  development."; option 3 prints the same message then `exit(0)`. `clear_console` runs `cls` on
  Windows and `clear` elsewhere; `press_enter_to_continue` waits for Enter and clears the screen.
  ([`3b421c9`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/3b421c9))
- ASCII-art assets `data/title.md` ("PVZ FUZION" banner) and `data/logo.md` (large ASCII logo);
  neither is read by the console in this range.
  ([`10e58e1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/10e58e1))
- Empty placeholder `app/src/parser/health.py` for the future file-integrity check.
  ([`b142831`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b142831))

## Notes

- No tag and no published artefact cover this range; `pyproject.toml` declares `python_console`
  version 0.1.0 throughout (never bumped). The TypeScript rewrite that follows does not reuse this
  code.
- Two author names appear (`LINDECKER Charles`, and `Shirou-Emiya2420` on cb28341 and 10e58e1) but
  both use the same e-mail address (charles.lindecker@outlook.fr): same person under a different git
  identity.
- Commit subjects are in English with a loose Conventional Commits style (space before the colon,
  e.g. `feat(parser) :`); the first three commits (`Initial commit`, `init`, `doc`) have no type.
  Commit cb28341 carries two subjects on two lines (parser + comparator), shown joined in the commit
  list below.
- `pyproject.toml` description and the first report builder draft (10e58e1) are in French; the
  README, console and later reports are in English.
- Committed build artefacts: `src/python_console.egg-info/` was added in 52ddceb and regenerated in
  cb28341 (PKG-INFO embeds the README, requires.txt gains `pyinstaller`) before being deleted in
  00f242c; `__pycache__/*.pyc` files were committed in cb28341 and 10e58e1 and deleted in 3b421c9.
- The prototype hard-codes the data source as a sibling directory `../../PvZ_Fusion_Translator`
  relative to `console.py` (`../../../` from `entry_comparator.py` in its original `__main__` block)
  and `English` as the reference locale; there is no configuration. Reports are written relative to
  the current working directory (`reports/...`), which is why `src/reports` is git-ignored.
- `pyinstaller` is listed as a runtime dependency (cb28341) and was documented with `pip install
  pyinstaller` in the README (0745127) but is never used; packaging is done with the
  standard-library `zipapp`.
- Between 08837bf and b142831 running `python src/console.py` directly did nothing (no `__main__`
  guard), although the README of 00f242c documents that command; only the zipapp entry point worked.
- Typo preserved in code: `get_achivements` in `parser.py`; console banner spells "Consol".
