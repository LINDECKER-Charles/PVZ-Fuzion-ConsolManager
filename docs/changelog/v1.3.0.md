v1.3.0 is still the Python-era CLI (src/pvz_console, shipped through the Node wrapper
bin/pvzf-console.js which builds a zipapp on first run). It adds a third entry to Translator Tools,
"Check duplicates", which scans each locale's Strings files for keys repeated in the raw JSON and
for values shared by several keys and writes a duplicates.md report per affected locale. It also
adds JSON diff export next to the Markdown reports: the interactive "missing translations" flow asks
"Also export JSON diff files alongside reports?" and the `diff` subcommand gains a `--with-diff`
flag; the JSON files mirror the shape of the source localisation files so they can be merged back
directly. The rest of the release is infrastructure: an MIT LICENSE, a pytest suite (162 tests) with
coverage config, a node:test + c8 suite (22 tests) for the two JS wrapper scripts, the first GitHub
Actions CI workflow (Python 3.10-3.12 matrix and Node 20/22 matrix with 75% coverage gates and
job-summary tables), and the npm engines requirement raised from Node >=14 to >=20.

## Added

- New Translator Tools menu entry `3. Check duplicates — duplicate keys & repeated values`
  (`_tool_duplicate_checker` in `cli/app.py`). The tool
  (`src/pvz_console/tools/duplicate_checker.py`, `check_locale_duplicates`) scans, for each selected
  locale (single or All), the Strings files `translation_strings`, `regexs`, `tips_iz`, `tips_fs`,
  `abyss_buffs` (flat layout) and `travel_buffs` (nested layout, flattened to `category:key`); a
  missing file is marked `missing` and skipped. Duplicate keys are detected in the raw JSON text via
  `json.load(object_pairs_hook=...)` because the standard loader silently keeps the last value (a
  parse error returns the counts gathered so far); repeated values ignore empty/non-string values
  and are grouped as (value, [keys]) sorted by number of keys then value. Per locale the console
  prints `No duplicates found.` or the totals plus one line per file with hits and the report path,
  then a grand total across locales. `build_duplicates_report` (in `reporting/markdown.py`) writes
  `reports/<locale>/duplicates.md` with, per file, a `Duplicate keys` table (key, occurrences) and a
  `Repeated values` table (value, keys sharing it); it returns `None` and writes nothing for a clean
  locale.
  ([`0770ce8`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/0770ce8))
- JSON diff export alongside the Markdown reports (`src/pvz_console/reporting/diff_json.py`). Each
  translation type gets a builder: `plants_diff.json`, `zombies_diff.json`, `achievements_diff.json`
  (wrapped as `{"plants"|"zombies"|"achievements": [raw missing entries]}`), `strings_diff.json`,
  `regexs_diff.json`, `tips_iz_diff.json`, `tips_fs_diff.json`, `abyss_buffs_diff.json` (flat `{key:
  source_value}`, empty string when the source value is None) and `travel_buffs_diff.json` (nested
  `{category: {key: source_value}}` rebuilt by splitting the flattened key on the first `:`). Files
  are written in `reports/<locale>/`, UTF-8 with `ensure_ascii=False`, `indent=2` and a trailing
  newline, printing `✅ Diff generated: <path>`, and only when there is at least one missing entry.
  The shapes deliberately mirror the source localisation files so the output can be merged back in
  directly.
  ([`8a219bb`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/8a219bb))
- Interactive `Show missing translations` flow now asks `Also export JSON diff files alongside
  reports? (y/N)` after the type selection (new `_ask_yes_no` helper: empty input returns the
  default, otherwise y/yes/o/oui count as yes) and prints `JSON diff files written next to the
  markdown reports.` when enabled. Every `_run_*` function, `_run_all` and the `TranslationType.run`
  callable take a new `with_diff: bool = False` argument; the invalid-choice check now runs before
  the new prompt instead of after locale selection.
  ([`8a219bb`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/8a219bb))
- New `--with-diff` flag on the non-interactive `pvzf-console diff --lang <locale> [--out DIR]`
  subcommand (help: "Also write JSON diff files (one per type) next to the reports.");
  `_cmd_diff(lang, out, with_diff=False)` forwards it to `_run_all`.
  ([`8a219bb`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/8a219bb))
- Added `LICENSE` (MIT, Copyright (c) 2026 Charles Lindecker), matching the `license` field already
  declared in `package.json`.
  ([`8a219bb`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/8a219bb))

## CI

- First GitHub Actions workflow `.github/workflows/ci.yml` (`CI`), triggered on push and
  pull_request for `main` and `dev`. Job `test` (`Tests (Python X)`, `fail-fast: false`) runs a
  Python matrix (3.10, 3.11, 3.12) with `actions/checkout@v4` and `actions/setup-python@v5` (pip
  cache), installs `pip install -e ".[dev]"`, runs `pytest --cov --cov-report=term-missing
  --cov-report=xml --cov-fail-under=100` and uploads `coverage.xml` as artifact `coverage-xml` (14
  days, `actions/upload-artifact@v4`) from the 3.12 leg.
  ([`8a7bad6`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/8a7bad6))
- Added job `test-js` (`JS tests (Node X)`, matrix 20 and 22, `fail-fast: false`, with Python 3.12
  installed because `build.js` needs it for zipapp): `actions/setup-node@v4` with npm cache, `npm
  install`, then `npm run test:cov`; the Node 22 leg uploads `coverage/lcov.info` as artifact
  `js-coverage-lcov` (14 days). In the same commit the Python gate was lowered from
  `--cov-fail-under=100` to `75`, and the JS gate is set to 75% lines/functions/branches/statements
  in the `test:cov` script (the commit subjects still say "100% coverage"; the CI step was still
  named "100% gate").
  ([`14b480a`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/14b480a))
- Coverage tables rendered in the GitHub job summary: both jobs pipe their output through `tee`
  (`pytest-output.txt`, `js-output.txt`) and an `if: always()` step `Render coverage in job summary`
  extracts the coverage table (`sed -n '/^Name *Stmts/,/^TOTAL/p'` for pytest, `awk
  '/^-+\|/{table=1} table'` on the c8 table for JS) into `$GITHUB_STEP_SUMMARY` under a `## Python X
  — coverage` / `## Node X — coverage` heading. The JS step name was corrected from "100% gate" to
  "75% gate". A workflow-level `env: FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: "true"` was added to work
  around the Node 20 runner deprecation (link to the 2025-09-19 GitHub changelog in a comment).
  ([`80c35d9`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/80c35d9))
- Action versions bumped instead of forcing the Node 24 runtime: `actions/checkout` v4 → v6 (test
  job in 8f23bbf, test-js job in 57735aa), `actions/setup-python` v5 → v6, `actions/setup-node` v4 →
  v5, `actions/upload-artifact` v4 → v5 (57735aa) then v5 → v7 (f9a4ad0); the
  `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24` env introduced in 80c35d9 was removed again in 57735aa. Three
  successive commits share the subject `fix(ci) : update node version`.
  ([`8f23bbf`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/8f23bbf),
  [`57735aa`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/57735aa),
  [`f9a4ad0`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/f9a4ad0))
