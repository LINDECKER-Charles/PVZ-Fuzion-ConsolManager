Minor release centred on one user-facing change: `settings.json` moves out of the installed package
into the per-user config directory (macOS Application Support, XDG on Linux, `%APPDATA%` on
Windows), with a `PVZF_CONSOLE_SETTINGS` override, a read-only fallback to the legacy in-package
file so upgrades from ≤ 1.4.1 are seamless, and save failures reported as warnings instead of
crashing the CLI. No CLI command, prompt or output format changed. The rest of the range is
infrastructure: the CI test matrix gains one macOS and one Windows job, Dependabot is reconfigured
to monthly grouped updates behind a cooldown (fixing two defects in the previous config), and
Dependabot PRs #11–#17 bump GitHub Actions and dev dependencies. The version bump to 1.5.0 was never
tagged or published; everything here shipped with 1.6.0.

## Added

- `settings.json` is now stored in the per-user config directory instead of inside the installed
  package (`src/settings.ts`, new `userConfigDir()`): `%APPDATA%\pvzf-console\settings.json` on
  Windows (falling back to `%LOCALAPPDATA%`, then `~\AppData\Roaming`), `~/Library/Application
  Support/pvzf-console/settings.json` on macOS, `$XDG_CONFIG_HOME/pvzf-console/settings.json` or
  `~/.config/pvzf-console/settings.json` elsewhere. An absolute `$XDG_CONFIG_HOME` is honoured on
  every POSIX platform, macOS included; a relative one is ignored per the XDG spec. The home
  directory is resolved from `$HOME`, then `%USERPROFILE%`, then `os.homedir()`. Rationale: a global
  install in a root-owned prefix (`/usr/local/lib/node_modules`, `C:\Program Files\nodejs`) was not
  writable by a normal user.
  ([`3343120`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/3343120))
- New `PVZF_CONSOLE_SETTINGS` environment variable (exported constant `SETTINGS_ENV_VAR`) pins the
  settings file to an explicit path (`~` is expanded, path resolved to absolute) for portable
  installs and CI. `settingsPath()` precedence is now: (1) `PVZF_CONSOLE_SETTINGS`, (2) the per-user
  config directory, (3) the legacy in-package path when `userConfigDir()` returns `null` (no
  resolvable home, e.g. bare containers). New exported helper `legacySettingsPath()` (=
  `<REPO_ROOT>/settings.json`).
  ([`3343120`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/3343120))
- `[3] Settings` → current settings now print a `Settings file` line showing the active path
  (`App.showCurrentSettings` in `src/cli/app.ts`).
  ([`3343120`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/3343120))
- Upgrade path from ≤ 1.4.1: `loadSettings()` reads the per-user file first and, when it is absent
  or unusable (unreadable, invalid JSON, non-object), falls back to the legacy in-package
  `settings.json` (skipped when both paths are identical); the next save writes the per-user file
  and leaves the legacy copy untouched, so an older install alongside keeps working (the two stop
  tracking each other from then on). Covered by new tests in `tests/settings.test.ts` (env override
  and `~` expansion, save reporting instead of throwing, per-user dir on macOS / POSIX / Windows,
  absolute-vs-relative XDG, legacy read when no per-user file, migration on save, per-user file wins
  when both exist, defaults when the legacy file is corrupt).
  ([`3343120`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/3343120))

## Changed

- `saveSettings()` no longer throws: it returns `null` on success or a `"<path>: <reason>"` string
  on failure (`mkdirSync` + `writeFileSync` wrapped in try/catch). `App` gains `persistSettings()`,
  which every settings screen (project root, source locale, colours, density, emoji/banner toggles,
  reset, Trello label) now calls; a failure is surfaced as the warning `Settings could not be saved
  — …` while the in-memory change stays applied for the session. The `AppDeps.saveSettings`
  signature changes to `(settings) => string | null` (test fake in `tests/cli/_fakes.ts` updated to
  return `null`).
  ([`3343120`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/3343120))

## CI

- `.github/workflows/ci.yml`: the `test` job is now a platform matrix — Node 20 and 22 on
  `ubuntu-latest`, plus one `macos-latest` and one `windows-latest` job on Node 22 (`include`
  entries) — because path handling and the per-user config directory differ per platform.
  `fail-fast: false` kept; job names become `test (<os>, node <version>)`. Subject uses a scope-less
  `ci:` prefix.
  ([`73012c3`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/73012c3))
- `.github/dependabot.yml` rewritten: version updates drop from weekly (`day: monday`) to monthly
  (05:00 Europe/Paris) and sit behind a cooldown (npm: `default-days` 14, 7 days patch, 14 minor, 30
  major; GitHub Actions: 14 days flat, since `semver-*-days` is npm-only). Security updates are
  unaffected (they ignore schedule, cooldown, groups and PR limits). `open-pull-requests-limit`
  lowered from 10 to 8 (npm) and from 5 to 3 (actions). Rationale in the commit body and a header
  comment: the package ships zero runtime dependencies and a single bundled `dist/cli.js`, so the
  risk being managed is a hijacked dev-dependency release, which is usually yanked within days.
  ([`9ede490`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/9ede490))
- Dependabot groups reworked to fix two defects: (1) `labels: [dependencies, security]` / `[ci,
  security]` pointed at labels that do not exist in the repo (Dependabot reported it on PR #2), so
  every Dependabot PR shipped unlabelled — the key is dropped to restore the default label; (2) the
  `dev-dependencies` catch-all (`dependency-type: development`, restricted to minor/patch) swallowed
  packages that matched earlier groups (PR #12 bundled eslint, typescript-eslint,
  @vitest/coverage-v8 and tsx). Groups are now `vitest` (`vitest`, `@vitest/*`), `eslint` (`eslint`,
  `eslint-*`, `@eslint/*`, `typescript-eslint`, `@typescript-eslint/*`, `globals` — the two
  typescript-eslint patterns move here from the old `typescript` group), `typescript` (`typescript`,
  `@types/*`), `build-tooling` (`tsup`, `tsx`, `esbuild`) and an `other-dev` catch-all (`*`) with
  explicit `exclude-patterns` mirroring the four groups; no group restricts update types, so
  lockstep pairs like `vitest` / `@vitest/coverage-v8` can no longer be split across PRs (the split
  in #4/#5 produced the broken tree repaired by 3026f97). GitHub Actions updates are grouped into a
  single `actions` group (`*`).
  ([`9ede490`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/9ede490))
- GitHub Actions bumps: `actions/setup-node` v6 → v7 in `ci.yml` (1 use) and `security.yml` (2 uses)
  (PR #11, merged 5ae3b43); `github/codeql-action` `init` and `analyze` pinned from `@v4` to
  `@v4.37.4` in `ci.yml` (PR #15, merged e1d4839).
  ([`35bff3e`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/35bff3e),
