First published release of the toolkit, still implemented in Python at this point. The original
three-module prototype (plants / zombies / achievements almanac diff with a minimal menu) is
replaced by a structured `src/pvz_console` package that covers every localisation file type of the
game (almanac entries, UI strings, regex, tips IZ/FS, abyss buffs, travel buffs), detects both
missing keys and empty values, and adds two translator tools: an all-or-nothing tips migration and a
per-category Trello CSV export with a generated import guide. A headless `diff --lang` sub-command,
a persistent `settings.json`, a themeable TUI and project-root auto-discovery are introduced.
Distribution is set up as a single-file `dist/pvzf_console.pyz` (zipapp) built by `bin/build.js` /
`scripts/build.*`, wrapped in an npm package whose `pvzf-console` binary detects Python 3.10+ and
lazily rebuilds the archive; the final commit renames the package to
`@charles_lindecker/pvzf-console` and bumps it to 1.0.0.

## Added

- Five new translation types next to the existing Plants / Zombies / Achievements checks
  (`parsers/almanac.py`: `Almanac/LawnStringsTranslate.json`, `Almanac/ZombieStringsTranslate.json`,
  `Almanac/AchievementsTextTranslate.json`): Strings (UI) from `Strings/translation_strings.json`,
  Regex from `Strings/translation_regexs.json`, Tips (IZ + FS) from `Strings/tips_iz.json` and
  `Strings/tips_fs.json`, Abyss buffs from `Strings/abyss_buffs.json`, and Travel buffs from the
  nested `Strings/travel_buffs.json` (flattened to `category:id` compound keys). The flat-file diff
  (`parsers/strings.py`) reports both keys missing from the target locale and keys present with an
  empty value (`StringEntry.status` = `missing` | `empty`). Menu `[1] Show what's missing` lists
  them as `[0] All types`, `[1] Plants` … `[8] Travel buffs`; a missing `tips_*.json` / buff file is
  reported with a warning instead of crashing.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Headless CLI: `pvzf-console diff --lang <LOCALE> [--out <DIR>]` (argparse sub-command in
  `cli/app.py`, `prog="pvzf-console"`) runs every diff type for one locale and writes the reports
  under `<out>/<locale>/` (default `./reports`). Exit code `0` on success, `2` when the locale is
  unknown, is the source locale, or the project root is invalid. Without arguments the interactive
  TUI starts.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Translator tool `[2] > [1] Migrate tips`: `tools/tips_migration.py` builds `tips_iz.json` /
  `tips_fs.json` for one locale. Each `<project>/Dumps/tips_*.json` maps `tip_key → Chinese source
  text`; that text is looked up as a key of the locale's `translation_strings.json` and the output
  maps `tip_key → translation`. Contract: nothing runs if `translation_strings.json` is missing or
  empty, existing destination files are never overwritten, a missing dump source is skipped, and a
  file is only written when every source tip has a translation (otherwise the gap count is
  reported). Output is UTF-8-SIG JSON, indent 4. The picker is single-locale and excludes the source
  locale.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Translator tool `[2] > [2] Export Trello CSV`: `tools/trello_export.py` +
  `reporting/trello_csv.py` collect every untranslated entry of a locale as `TrelloCard`s and write
  one CSV per Trello list under `exports/<Locale>/` (`trello_Plants.csv`, `trello_Zombies.csv`,
  `trello_Achievements.csv`, `trello_Strings.csv`, `trello_Regex.csv`, `trello_Tips_IZ.csv`,
  `trello_Tips_FS.csv`, `trello_Abyss_Buffs.csv`, `trello_Travel_Buffs.csv`; empty lists produce no
  file). Columns `Name`, `Description`, `Labels`, `List` (all quoted); descriptions are ```` ```json
  ```` fenced (raw almanac entry, or `"key": "value"` for flat files), names truncated to 100 chars
  and descriptions to 15000 chars. A `trello_README.md` with the lists/label to create, per-list
  card counts and the *Import to Trello by Blue Cat* Power-Up walkthrough is generated alongside.
  The label comes from the `trello_label` setting, but the source locale is the hard-coded
  `config.SOURCE_LOCALE` (`English`), not the `source_locale` setting.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Persistent settings (`settings.py`, `AppSettings` dataclass) stored in `settings.json` at the
  install root, with keys `project_root`, `source_locale` (default `English`), `color` (`default`),
  `accent_color` (`cyan`), `density` (`comfortable`), `show_emoji` (`true`), `show_banner` (`true`),
  `trello_label` (`To be translated`). Unknown keys are ignored on load, an unreadable file falls
  back to defaults. New `[3] Settings` menu: `[1] Change PvZ_Fusion_Translator folder` (validated:
  directory must exist and contain `Localization/`), `[2] Change text color`, `[3] Change accent
  color`, `[4] Change spacing density`, `[5] Toggle emoji`, `[6] Toggle ASCII banner`, `[7] Change
  Trello label text`, `[9] Reset to defaults`, `[0] Back`. `source_locale` has no menu entry and can
  only be edited in the file.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Themeable TUI (`cli/theme.py`, `cli/menus.py`): 15 ANSI colour names (`default`, `red` … `white`
  plus `bright_*`), densities `compact` / `comfortable` / `spacious` (0 / 1 / 2 blank lines), emoji
  status icons with `[OK]` / `[!]` / `[X]` fallbacks, section headers, a locale picker rendered as a
  3-column grid accepting `*` for all locales (tools restrict to a single locale and exclude the
  source locale), and a banner renderer (`cli/banner.py`) that falls back to the package resource
  `pvz_console/data/title.md` via `importlib.resources` when running from a `.pyz`. Windows consoles
  get VT100 processing enabled through `kernel32.SetConsoleMode` and `stdout`/`stderr` reconfigured
  to UTF-8.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Project-root auto-discovery in `config.py`: `PvZ_Fusion_Translator/` is probed (non-recursively)
  next to the install, one level above it, in the current working directory and in its parent. The
  TUI warns at startup when the configured root is invalid and every tool is guarded by
  `_require_valid_project_root()` so `os.listdir` / `open` failures no longer surface as tracebacks.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- npm packaging: `package.json` (`pvzf-console` 0.3.0, MIT, `engines.node >= 14`, `bin.pvzf-console
  = bin/pvzf-console.js`, `files` = `bin/`, `dist/`, `src/`, `data/`, both READMEs, scripts `build`
  and `prepublishOnly` = `node bin/build.js`). The `bin/pvzf-console.js` wrapper rebuilds
  `dist/pvzf_console.pyz` from the shipped sources when the archive is missing, then spawns `python
  dist/pvzf_console.pyz <args>` with inherited stdio and propagates the exit status. It delegates
  Python detection and the build itself to `./build` (`bin/build.js`), which is only added in
  40de05e.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1),
  [`40de05e`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/40de05e))
- Python packaging moved to a root `pyproject.toml`: project `pvz-console` 0.2.0, `requires-python
  >= 3.10` (the code uses `match` statements), no runtime dependencies, optional `build` extra
  (`pyinstaller`), setuptools `src/` layout and console script `pvz-console =
  pvz_console.cli.app:main`. `src/pvz_console/__main__.py` enables `python -m pvz_console`;
  `__init__.py` exposes `__version__ = "0.2.0"`.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Cross-platform build tooling for the single-file archive: `bin/build.js` (Node module exporting
  `buildPyz`, `detectPython`, `pythonMissingMessage`, `PYTHON_DOWNLOAD_URL`; `detectPython` tries
  `python3`, `python`, `py` and requires >= 3.10; `buildPyz` stages `src/pvz_console/` plus `data/`
  into a temp directory, runs `python -m zipapp … -m pvz_console.__main__:main -o
  dist/pvzf_console.pyz`, copies `README.dist.md` to `dist/README.md`, cleans up). Shell
  counterparts `scripts/build.sh` / `scripts/build.bat` do the same staging and zipapp call but only
  check for any `Python 3.*` on PATH (`python`, `python3`, `py`). `scripts/run.sh` /
  `scripts/run.bat` launch the TUI from source with `PYTHONPATH=src` and `python -m pvz_console`.
  This commit completes b3d1ff1, whose `bin/pvzf-console.js` already required `./build`.
  ([`40de05e`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/40de05e))

## Changed

- Code base restructured from the flat `app/src/` prototype (`console.py`, `interface/`, `parser/`,
  `report_builder/`) into the `src/pvz_console/` package with explicit layers: `cli/` (app, menus,
  theme, banner), `core/` (`models.py` dataclasses
  `AlmanacEntry`/`Plant`/`Zombie`/`Achievement`/`StringEntry`/`TrelloCard`, `diff.py`), `parsers/`
  (`loaders.py`, `almanac.py`, `strings.py`), `reporting/` (`markdown.py`, `trello_csv.py`),
  `tools/`, plus `config.py` and `settings.py`. Banner assets moved from `app/data/` to `data/`.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Main menu renumbered and reworked: `[1] Show what's missing`, `[2] Translator tools`, `[3]
  Settings`, `[0] Exit` (previously `[0] Show what's missing`, `[1] Check files integrity` and `[2]
  Settings` as "under development" stubs, `[3] Exit`). Translation-type selection uses `[0] All
  types` instead of `[-1] All`; the locale picker uses `*` for all locales instead of `[-1] All`
  (the old picker also returned every locale on any invalid input).
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Markdown report layout is now grouped by locale: `reports/<Locale>/missing_plants.md`,
  `missing_zombies.md`, `missing_achievements.md`, `missing_strings.md`, `missing_regexs.md`,
  `missing_tips_iz.md`, `missing_tips_fs.md`, `missing_abyss_buffs.md`, `missing_travel_buffs.md`
  (previously `reports/<type>/missing_<type>_<Locale>.md`). Almanac reports print each missing entry
  as a fenced JSON block of the raw source object (instead of separate Introduce / Info / Cost
  paragraphs and a table of contents); flat reports have a *Missing Keys* JSON object section and an
  *Empty Values* table. Nothing is written when there is nothing to report.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- Missing-entry detection is set-based (`core/diff.py::missing_by_id`, O(n + m)) instead of the
  previous nested-loop `compare_lists`; entity dataclasses keep the untouched source dict in `raw`.
  `loaders.load_json` reads UTF-8-SIG and returns `{}` for missing files so optional per-locale
  files do not need special casing.
  ([`b3d1ff1`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/b3d1ff1))
- npm package renamed from `pvzf-console` to the scoped `@charles_lindecker/pvzf-console` and
  version bumped 0.3.0 → 1.0.0 in `package.json`.
  ([`0b5e893`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/0b5e893))
