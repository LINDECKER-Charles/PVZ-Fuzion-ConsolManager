v1.2.0 is a small release of the Python-era console (src/pvz_console, shipped through the npm
wrapper @charles_lindecker/pvzf-console). The reference locale used to detect missing translations —
the existing `source_locale` setting, previously only editable by hand in settings.json — becomes
editable from the Settings menu, and gains a new "Dumps" pseudo-source that diffs every locale
against the raw game dumps in PvZ_Fusion_Translator/Dumps/ instead of Localization/<locale>/. The
Trello CSV export now honours that setting instead of a hard-coded "English" source. The two
remaining commits only bump package.json from 1.0.0 to 1.1.0 and then to 1.2.0.

## Added

- New Settings menu entry "[2] Change source locale (reference)" in the interactive console
  (src/pvz_console/cli/app.py, `_edit_source_locale`). It requires a valid project root, offers the
  special value "Dumps" first followed by the locales found under Localization/, validates the
  choice with `AppSettings.validate_source_locale()`, persists it to settings.json under the
  pre-existing `source_locale` key (default "English", formerly hand-edited only) and reverts to the
  previous value on error. Existing entries are renumbered: text color 2→3, accent color 3→4,
  density 4→5, emoji 5→6, banner 6→7, Trello label 7→8; "[9] Reset to defaults" and "[0] Back" are
  unchanged.
  ([`e0b34fd`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/e0b34fd))
- "Dumps" source mode in src/pvz_console/parsers/loaders.py: `DUMPS_DIRNAME`/`DUMPS_SOURCE`
  sentinels (both "Dumps"), path resolvers `dumps_root`, `is_dumps_source`, `source_almanac_path`,
  `source_strings_path`, the private `_dumps_path` and the remapping tables
  `_ALMANAC_DUMP_FILENAMES` / `_STRINGS_DUMP_FILENAMES`. When the source is "Dumps", reference files
  are read from PvZ_Fusion_Translator/Dumps/ with filename remapping:
  LawnStringsTranslate.json→LawnStrings.json, ZombieStringsTranslate.json→ZombieStrings.json,
  AchievementsTextTranslate.json→AchievementsText.json, abyss_buffs.json→AbyssBuffData.json;
  translation_strings.json and translation_regexs.json have no Dumps equivalent and resolve to a
  non-existent path under Dumps/ so `load_json`'s missing-file branch yields an empty diff. A
  `source_has_file(root, source, kind, filename)` helper is also added but not called.
  ([`e0b34fd`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/e0b34fd))
- `AppSettings.validate_source_locale()` and `AppSettings.uses_dumps_source()` in
  src/pvz_console/settings.py (which now imports from parsers.loaders): the source must be an
  existing Localization/<locale>/ folder or, for "Dumps", an existing Dumps/ folder under the
  project root. When the project root is valid, the "Current settings" screen shows a valid/invalid
  badge next to the source locale, and the interactive startup warns when the configured source is
  invalid (pointing to "[3] Settings → Change source locale").
  ([`e0b34fd`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/e0b34fd))

## Changed

- Almanac loaders (`load_plants`, `load_zombies`, `load_achievements` in
  src/pvz_console/parsers/almanac.py) and string diffs (`diff_file`, `diff_nested_file` in
  src/pvz_console/parsers/strings.py) resolve the source side through `source_almanac_path` /
  `source_strings_path`, so every report, scan and export follows the configured source (locale
  folder or Dumps/). Target locales are still read from Localization/<locale>/.
  ([`e0b34fd`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/e0b34fd))

## Fixed

- Trello export ignored the configured source locale: `collect_cards` and `export_trello` in
  src/pvz_console/tools/trello_export.py always diffed against the hard-coded `config.SOURCE_LOCALE`
  ("English"). They now take a `source` keyword parameter (default unchanged) and the CLI's
  `_tool_trello_export` passes `settings.source_locale`.
  ([`e0b34fd`](https://github.com/LINDECKER-Charles/PVZ-Fuzion-ConsolManager/commit/e0b34fd))
